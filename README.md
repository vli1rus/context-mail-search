# Контекст — умный поиск в почте

Веб-прототип для кейса VK Tech на хакатоне ФПМИ. Поиск принимает обычные фразы и номера заказов, показывает фрагмент найденного письма и позволяет собрать письма из нескольких поисков в подборку.

## Быстрый запуск на Windows

Скачайте файл [START_CONTEXT.py](START_CONTEXT.py) через кнопку **Download raw file** и откройте его в Python 3.11 или новее. Браузер откроется автоматически. Оставьте окно запуска открытым, пока пользуетесь демо.

## Запуск одной командой

Нужен Python 3.11 или новее. Распакуйте проект и выполните команду из папки, где находится этот README. Демо использует стандартную библиотеку и работает без интернета.

```sh
python -m mailsearch.server --demo
```

Откройте <http://127.0.0.1:8765>. В деморежиме есть 30 тестовых писем, три ящика и примеры запросов. Интерфейс и движок работают локально. Команда ниже принимает официальный ZIP целиком либо папку с извлечёнными файлами. Если `mipt_mail_search_participants.zip` лежит в корне проекта, достаточно `python -m mailsearch.server`.

```sh
python -m mailsearch.server --dataset mipt_mail_search_participants.zip
```

Импорт использует `doc_id`, `synthetic_user`, `doc`, `doc_dt`. При наличии `manifest.json` сверяются контрольные суммы. `synthetic_user` задаёт ящик для каждого бенчмарк-запроса. Письма с известной датой после `query_date` исключаются, а письма без даты остаются доступными. Выражения вроде «вчера» повышают позиции писем подходящего дня. Отдельные фильтры «С» и «По» ограничивают выдачу заданным периодом.

[Архив участников от организаторов](https://cloud.mail.ru/public/8S62/oQDJV17v6)

## Как ранжируется выдача

1. Лексический индекс с весами для темы и отправителя находит точные слова и близкие словоформы.
2. E5 ищет по фрагментам. Ранг письма учитывает наиболее близкий фрагмент, даже если он в конце письма. В режиме без E5 второй источник кандидатов сопоставляет лексику по темам и действиям, характерным для писем. Интерфейс обозначает этот режим как «По теме».
3. Объединяем ранги методом Reciprocal Rank Fusion. Точные номера и адреса влияют на порядок результатов даже при разнице в тире. Совпадение с вероятной датой повышает позицию внутри разрешённого набора писем.
4. В выдаче показываем цитату из оригинального письма и фактически сработавшие признаки. Для удобства найденные письма можно сохранить в подборку в браузере.

[Описание RRF](https://cormack.uwaterloo.ca/cormack/cormacksigir09-rrf.pdf)

## Проверка и выгрузка

```sh
python -m unittest discover -s tests -v
python -m mailsearch.evaluate --demo --repeat 20
python -m mailsearch.evaluate --dataset mipt_mail_search_participants.zip --k 1 5 10
python -m mailsearch.evaluate --dataset mipt_mail_search_participants.zip --mode smart --export-k 10 --output submission.jsonl
```

Режимы сравниваются на тех же запросах. Отчёт включает Recall, nDCG, MRR и отдельный MRR для запросов с одним релевантным письмом. Выгрузка в JSONL содержит по строке на запрос, например `{"query_id":"q1","doc_ids":["d7","d2"]}`. Точный отсев K и официальный формат нужно сверить с организаторами. Для другого файла запросов передайте `--queries PATH`, а при наличии разметки добавьте `--qrels PATH`.

`evaluate` измеряет поиск и подготовку фрагментов. Для замера HTTP запустите сервер и в другом терминале выполните команду ниже. Она читает серверное время из `Server-Timing`, включая формирование JSON выдачи, и отдельно сообщает время полного HTTP-обмена. `--queries` позволяет указать `queries_dev.jsonl`, если архив извлечён.

```sh
python -m mailsearch.loadtest --repeat 10 --workers 4
```

## Результаты разработки

На 24 размеченных демо-запросах Recall@5 вырос с 81,25% до 100%, а nDCG@10 — с 0,766 до 0,995. Сравнивались поиск по словам и гибрид без E5. p99 поиска на этих запросах составил 3,087 и 8,390 мс соответственно при 20 повторах. Это время ранжирования и подготовки фрагментов без HTTP-сериализации. Официальный корпус и веса E5 в этом прогоне отсутствовали.

## Сверка с требованиями сдачи

| Требование | Статус |
|---|---|
| Репозиторий с кодом и инструкцией запуска | Исходники и этот README в комплекте. Для сдачи требуется ссылка на репозиторий команды. |
| Рабочее веб-демо с просмотром писем | Доступно на localhost, организаторы допускают такой формат. |
| Для каждого `query_id` ранжированный список `doc_id` | Есть экспорт JSONL и проверка на демо. Точное значение K и итоговый формат файла нужно сверить с инструкцией приёма. |
| Защита с демонстрацией и объяснением решения | Готов трёхминутный сценарий. |
| Серверный p99 строго меньше секунды | Есть отдельный замер по `Server-Timing`. Значение на официальном наборе предстоит подтвердить. |
| Публичный запуск за +1 балл | Публичная ссылка пока отсутствует. |

## Конфигурация кандидата к сдаче

Проверенная конфигурация использует локальный режим smart без E5. Запускайте команды без параметра --model-dir. Лексический индекс формируется из выбранного корпуса при запуске. Пакет не содержит внешних индексов, кэша и весов. Официальный пакет данных требуется отдельно. См. [чеклист](RELEASE_CHECKLIST.md).
